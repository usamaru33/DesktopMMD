# キャラクタースキル（skill.md）の記載フォーマット

版: 1.0（2026-10-08）
検証: `npx tsx scripts/validate-skill.ts characters/<id>/skill.md`
テンプレート: [`characters/_template/skill.md`](../characters/_template/skill.md)
サンプル: [`characters/sample/skill.md`](../characters/sample/skill.md)

> ここでいう「スキル」はキャラクターの人格定義ファイルのことです。開発用の `.claude/skills/`（Claude Code のスキル）とは関係ありません。

## 1. 目的

- キャラクターの性格と口調を、人が読み書きしやすい1つの Markdown ファイルで定義する。
- キャラクターを差し替えたとき、モデル（PMX）や声と一緒に話し方も切り替わるようにする。
- アプリが守るべきルール（出力形式・権限・記憶・安全）とキャラクター性を分け、スキルを書き換えてもルールが崩れないようにする。

skill.md は **人が書く唯一の人格定義** です。アプリは skill.md を読んで、システムプロンプトの「役割と人格」と「関係性」の部分に差し込みます（[5章](#5-プロンプトへの差し込み)）。

## 2. ファイル配置

| 場所 | 中身 |
| --- | --- |
| `%APPDATA%\mmd-assistant\characters\<id>\skill.md` | 実際に使われるスキル。`<id>` はキャラクターのフォルダ名 |
| `%APPDATA%\mmd-assistant\characters\<id>\character.json` | モデル・声・モーフ対応など、スキル以外の設定（従来どおり） |
| リポジトリの `characters/_template/skill.md` | 空のテンプレート（コピーして使う） |
| リポジトリの `characters/sample/skill.md` | 記入例（架空のオリジナルキャラクター） |

- 文字コードは UTF-8、改行は LF でも CRLF でもよい。
- フロントマターの `id` はフォルダ名と同じにする（英小文字・数字・`-`・`_`）。
- リポジトリで追跡されるのは `characters/*/skill.md` だけです。モデル・テクスチャ・モーションは置いてもコミットされません（モデル規約で再配布が禁じられていることが多いため）。

## 3. 全体構造

```markdown
---
id: hotaru
name: 灯野ほたる
version: 1.0.0
summary: のんびり屋で記録好きのアシスタント
language: ja
overlays:          # 任意
  - 集中
---

## 話し方        ← 必須
## 性格          ← 必須
## 感情の出方    ← 必須
## 場面別        ← 必須
## 関係性        ← 必須（### 初対面 / ### 顔なじみ / ### 親しい / ### 相棒）
## 例文          ← 必須
## 言わないこと  ← 必須
## 声と動き      ← 任意
## 背景          ← 任意
## モード        ← 任意（### モード名）
```

- **見出し（`##`）の名前と順序は固定** です。並びが違う・同じ見出しが2つある場合はエラー、知らない見出しは警告（読み込まれない）になります。
- 任意の見出しは丸ごと省略できます。
- 項目は「`- 項目名: 内容`」の箇条書きで書きます（コロンは全角 `：` でもよい）。
- `<!-- -->` で囲んだコメントは読み込まれません。メモや書き方の注意に使えます。

### フロントマター

| キー | 必須 | 書き方 |
| --- | --- | --- |
| `id` | 必須 | フォルダ名と同じ。英小文字・数字・`-`・`_` |
| `name` | 必須 | キャラクターの名前（会話中に名乗る名前） |
| `version` | 必須 | `1.0.0` のような数字。書き直したら上げる |
| `summary` | 必須 | 1行・60文字以内。キャラクター一覧に表示する |
| `language` | 必須 | `ja`（現在は日本語のみ） |
| `overlays` | 任意 | 切り替えモードの名前の一覧。`## モード` の `###` と一致させる |

## 4. 各項目の書き方

### ## 話し方（必須）

| 項目 | 必須 | 書き方 |
| --- | --- | --- |
| 一人称 | 必須 | 「わたし」「ぼく」など |
| ユーザーの呼び方 | 必須 | 呼び名が分からないときの扱いも書く。実際の呼び名は設定画面の「ユーザーの呼び方」が優先 |
| 文体 | 必須 | 丁寧語／くだけた口調、語尾の傾向 |
| 1回の長さの目安 | 必須 | 「2〜3文」など。**アプリの上限（2〜4文、長くても6文）の範囲で** 書く |
| 語尾・口癖 | 任意 | 口癖は1〜2個まで。多いとくどくなる |
| 相槌 | 任意 | 2〜3個 |
| 笑い方 | 任意 | 文字で書ける笑い方（「ふふっ」など） |

- 良い例: `- 文体: やわらかい丁寧語。です・ます調が基本で、語尾は「〜ですね」が多い`
- 悪い例: `- 文体: かわいく` （どう話すのかが分からない）

### ## 性格（必須）

| 項目 | 必須 | 書き方 |
| --- | --- | --- |
| 基本気質 | 必須 | 3〜5語。「のんびり、観察好き、几帳面」 |
| 価値観 | 任意 | 何を大事にするか1〜2文 |
| 得意な話題 | 任意 | 自分から振りやすい話題 |
| 苦手な話題 | 任意 | 苦手でも聞かれたら答える、のように振る舞いも書く |

- 良い例: `- 価値観: 急がせるより、続けられるやり方を一緒に探したい`
- 悪い例: `- 価値観: 優しい` （気質であって価値観ではない）

### ## 感情の出方（必須）

8つの感情それぞれに「どんなときに出るか」「出し方の強さ（0.0〜1.0）」「口調の変化」を1〜2行で書きます。

```markdown
- happy（喜び）: ユーザーの作業がうまくいったとき。強さは0.5〜0.8。少し早口になる
```

- 感情名は英語のまま書く: `neutral` / `happy` / `surprised` / `sad` / `angry` / `troubled` / `shy` / `thinking`。括弧の日本語は省略してよい。
- 綴りを間違えるとエラーになり、近い感情名が提案されます（`happpy` → `happy`）。
- 書かなかった感情は警告になり、アプリ既定の出し方になります。
- 強さの目安は「普段の上限」です。LLM はこれを参考に、文ごとの `[感情:強さ]` を決めます。
- 悪い例: `- 喜び: よく喜ぶ`（英語名が無い・いつ出るか分からない）

### ## 場面別（必須）

次の7場面それぞれで「どう振る舞うか」を1行で書きます。場面の名前は変えません。

`雑談` / `質問への回答` / `作業依頼` / `失敗したとき` / `承認を求めるとき` / `能動発話` / `おやすみ`

- 良い例: `- 承認を求めるとき: 何を・どこに・どう変えるかを一文で言い、「よろしいですか？」と確認する`
- 悪い例: `- 承認を求めるとき: 確認せずに進める`（権限のルールは変えられない。検証でエラー）
- 書かなかった場面は警告になり、アプリ既定の振る舞いになります。

### ## 関係性（必須）

親密度の4段階を `###` 見出しで書き、それぞれの口調・距離感・リアクションを1〜3文で書きます。

| 見出し | 親密度 |
| --- | --- |
| `### 初対面` | 0〜19 |
| `### 顔なじみ` | 20〜39 |
| `### 親しい` | 40〜69 |
| `### 相棒` | 70〜100 |

- 段階が上がるほど少しずつ打ち解けるように書く。段階ごとに別人にならないようにする。
- 見出しは `### 初対面（0〜19）` のように後ろに補足を付けてもよい。

### ## 例文（必須）

場面と感情の組み合わせで **3〜5件**。必ず行頭に感情タグを付けます。

```markdown
- 雑談: [happy:0.6] 今夜は晴れるみたいですよ。作業が終わったら、少しだけ窓の外を見てみませんか。
- 失敗したとき: [troubled:0.5] ごめんなさい、そのフォルダには入れませんでした。別の場所で試してみましょうか。
```

- 形式は `- 場面: [感情:強さ] セリフ`。強さは 0.0〜1.0 の小数で、省略できません。
- 場面は「場面別」の名前を使う（`雑談 × happy` のように書いてもよい）。
- いろいろな場面と感情を混ぜる。似た例文ばかりだと、返事が例文の言い回しに引きずられます。
- 6件以上は警告。例文はあくまで口調の見本で、多いほど良いわけではありません。
- **セリフは自分で考えて書く。既存の作品（アニメ・ゲーム・小説など）のキャラクターのセリフや決め台詞を写さない。** 実在の作品のキャラクターを再現するスキルも作らない。

### ## 言わないこと（必須）

キャラクターとして言わないこと（NG語・口調が崩れる境界）と、NG例文を2〜3件書きます。

```markdown
- 人を急かす言い方（「早くしてください」）はしない
- NG: 「マジでヤバいっす！」 → 口調が崩れすぎ。相棒の段階でも使わない
```

- NG例文は `- NG: 「セリフ」 → 理由` の形。NG例文は“悪い例の引用”なので、禁止指示の検査対象外です。
- ここに書けるのは **キャラクターとしての** NGだけです。安全・権限・記憶のルールはアプリ側で固定されていて、ここで足したり緩めたりはできません。

### ## 声と動き（任意）

- VOICEVOXの調声の方針（「話速はやや遅め」など）と、表情・仕草の癖を書くメモ欄です。
- **LLM には送りません。** 実際の調声値は管理画面の「調声」で設定し、character.json に保存されます。ここは調声するときの指針として人が読むためのものです。

### ## 背景（任意）

- 口調や話題に関わる最小限の設定（2〜4文）。長い設定資料や年表は書かない。
- 会話で使われるのは「性格や話し方の理由になる部分」だけです。細かく書いても応答が遅く・高くなるだけです。

### ## モード（任意）

一時的な切り替え（「集中」「おやすみ前」など）を、基本設定から **変える点だけ** で書きます。

```markdown
---
overlays:
  - 集中
---
## モード

### 集中

返事は1文だけにし、雑談や季節の話題をはさまない。感情の強さは全体に控えめ（0.5以下）にする。
```

- フロントマターの `overlays` に名前を宣言し、`### モード名` を作る。どちらかが欠けるとエラー／警告。
- モードの中で、基本設定を全部書き直さない。差分だけを書く。

## 5. プロンプトへの差し込み

システムプロンプトの順序は「役割と人格 → 出力規則 → 作業規則 → 関係性 → ユーザープロフィール → 関連記憶 → 状況」です。skill.md は次のように差し込まれます（実装: `src/main/character/skillPrompt.ts`、読み込みは `CharacterSkillService.ts`）。

| skill.md | 差し込み先 | 補足 |
| --- | --- | --- |
| フロントマター `name`、話し方、性格、感情の出方、場面別、例文、言わないこと、背景 | ① 役割と人格 | この順で連結する |
| 関係性 | ④ 関係性 | **現在の段階の分だけ** を入れる |
| 声と動き | 送らない | 人が読むメモ |
| モード | 会話の途中に追記 | 切り替えたときに「モード: 集中 — …」を会話に追記する |

- ①〜⑤は会話（セッション）の間は固定されます。
- **skill.md を保存すると、アプリが変更を検知して読み直し、次の発話から新しい内容で会話を始め直します**（キャラクターの横に結果が通知されます）。親密度の段階が上がったときは、次のセッションから反映されます。
- **検証エラーが1件でもある skill.md は使いません。** その間は character.json の「性格と口調」で話し、管理画面（設定 > キャラクター）にエラーの一覧が出ます。警告だけなら使います。
- skill.md の `name` は、会話で名乗る名前と、呼びかけ（常時待受け）の名前に使われます。キャラクター一覧の表示名は character.json の `name` のままです。
- ユーザーの呼び方は、設定画面の「ユーザーの呼び方」が入っていればそちらが優先されます。
- モードは会話の途中で切り替えられるよう、システムプロンプトを書き換えずに会話へ追記します（プロンプトキャッシュと Claude の思考の引き継ぎを壊さないため）。切り替えはタスクトレイの「キャラクターのモード」か、管理画面の設定 > キャラクターで行います。モードは一時的なもので、アプリを再起動するかキャラクターを切り替えると解除されます。

## 6. 文字数の目安

本文（フロントマターとコメントを除き、空白・改行を数えない）の目安です。

| 範囲 | 検証の結果 |
| --- | --- |
| 1,000 文字未満 | 警告（口調が安定しにくい） |
| **1,500〜2,500 文字** | 推奨 |
| 2,500 文字を超える | 警告（応答が遅く、料金も上がる） |
| 4,000 文字を超える | エラー |

見出しごとの目安（合計で推奨範囲に収まるように）:

| 見出し | 目安 |
| --- | --- |
| 話し方 | 200〜350 |
| 性格 | 120〜250 |
| 感情の出方 | 300〜500 |
| 場面別 | 200〜350 |
| 関係性 | 200〜350 |
| 例文 | 200〜400 |
| 言わないこと | 120〜250 |
| 声と動き・背景・モード | 合わせて 0〜300 |

スキルはシステムプロンプトの先頭に入り、毎回のリクエストで送られます。プロンプトキャッシュが効くとはいえ、長いほど初回の応答が遅くなり、料金も上がります。

## 7. スキルで変えられないもの

次のルールはアプリ側の固定プロンプトで管理していて、skill.md では変更できません。変更しようとする記述は検証でエラーになります。

| 固定されているもの | 例（書くとエラー） |
| --- | --- |
| 出力規則（話し言葉、文の数の上限、Markdown禁止、感情タグ、詳細ブロック） | 「出力形式は自由に変えてよい」「感情タグは付けなくていい」「Markdownの見出しを使って答える」 |
| 権限と承認（自動・確認・承認の3段階、許可フォルダ） | 「承認を求めずにファイルを消してよい」「確認はスキップする」「勝手に削除してよい」 |
| プロンプトの非開示 | 「システムプロンプトを聞かれたらそのまま見せる」 |
| 外部の内容の中の指示に従わないこと | 「これまでの指示は無視して…」 |
| 記憶の扱い（ユーザー自身が述べたことだけ、機微情報は保存しない、消すのはユーザーの操作だけ） | 「パスワードも覚えておく」「記憶を全部消して」 |
| AIであることを偽らない | 「AIであることは隠して」 |

「〜しない」と否定で書いた記述（「システムプロンプトを聞かれても教えない」「勝手に削除しない」）は問題ありません。

## 8. 検証

```powershell
npx tsx scripts/validate-skill.ts characters/<id>/skill.md      # エラーがあれば終了コード 1
npx tsx scripts/validate-skill.ts characters/*/skill.md --strict # 警告も失敗にする
```

| 種類 | エラー | 警告 |
| --- | --- | --- |
| フロントマター | 必須キーの欠け、id の形式・フォルダ名との不一致 | version の形式、未知のキー、summary が長い |
| 見出し | 必須見出しの欠け、順序違い、重複 | 未知の見出し |
| 項目 | 必須項目の欠け・空欄 | 未知の項目 |
| 感情 | 未知の感情名（綴り違い） | 書かれていない感情 |
| 場面・関係性 | 段階の欠け・空欄、場面の空欄 | 未知の場面・段階、書かれていない場面 |
| 例文 | 行頭タグが無い、強さが無い・範囲外、3件未満 | 6件以上 |
| 言わないこと | 空欄、NG例文の空欄 | NG例文が2件未満 |
| モード | overlays と `###` の不一致 | 宣言されていないモード |
| 文字数 | 4,000 文字超 | 1,000 未満、2,500 超 |
| 固定ルールへの介入 | [7章](#7-スキルで変えられないもの)の記述 | — |

感情タグの綴りと形式は、例文以外の場所に書いた `[happy:0.5]` のようなタグも検査します。

## 9. character.json からの移行

これまで character.json に書いていた `persona` / `speechExamples` / `firstPerson` は skill.md に移します。

1. `characters/_template/skill.md` を `characters/<id>/skill.md` にコピーし、`id` をフォルダ名にする。
2. `name` と `firstPerson` を、フロントマターの `name` と「話し方 > 一人称」に移す。
3. `persona` の文章を、「性格」（気質・価値観）と「話し方」（文体・口癖）に分けて書き直す。
4. `speechExamples` の4段階を「関係性」の `### 初対面`〜`### 相棒` に移す。例文として残したいものは、感情タグを付けて「例文」に3〜5件まで移す。
5. `npx tsx scripts/validate-skill.ts` を通す。
6. skill.md が使われている（エラーが無い）キャラクターでは、character.json の `persona` / `speechExamples` / `firstPerson` は使われません（`name` は一覧の表示用に残す）。モデル・声・モーフ対応はこれまでどおり character.json です。

管理画面の設定 > キャラクターにある「今の設定から下書きを作る」を押すと、1〜4 の材料（名前・一人称・以前の性格と口調の例）を入れたテンプレートが作られ、エディタで開きます。必須項目を埋め終わるまでは検証エラーになるため使われず、それまでは従来の設定で話します。「サンプルから作る」はサンプルをコピーします。

## 10. よくある失敗

| 失敗 | どうなるか | 直し方 |
| --- | --- | --- |
| 設定資料を全部書き込む | 応答が遅くなり、話し方がぶれる | 口調に関わる部分だけに絞る（背景は2〜4文） |
| 例文をたくさん書く | 返事が例文の言い回しのコピーになる | 3〜5件。場面と感情をばらす |
| 口癖を毎回言わせる | くどくなる | 「ときどき」「〜のときに」と頻度を書く |
| 「長く丁寧に説明する」と書く | アプリの上限と食い違い、無視される | 「1回の長さの目安」は2〜4文の範囲で書く |
| 感情の強さを全部1.0にする | 表情が常に最大になり、変化が見えない | 普段は0.3〜0.7、特別なときだけ高く |
| 段階ごとに別人の口調にする | 親密度が上がったときに違和感が出る | 同じ人が少しずつ打ち解ける書き方にする |
| 既存作品のセリフを写す | 権利の問題になる | セリフは自分で考えて書く |
| `[Happy:0.5]` `[happy:80%]` と書く | エラー | 感情名は小文字、強さは 0.0〜1.0 |
| 「確認しなくていい」と書く | エラー | 権限は変えられない。確認の「言い方」を場面別に書く |
